## 架构设计

### Evidence Repository Pattern

```python
class EvidenceRepository:
    """Evidence repository for Phase 2 database operations."""
    
    def __init__(self, session: AsyncSession):
        self.session = session
    
    # VerificationPoint operations
    async def add_verification_point(self, vp: VerificationPoint) -> None
    async def get_verification_point(self, verification_point_id: str) -> VerificationPoint | None
    async def get_verification_points_for_claim(self, claim_id: str) -> list[VerificationPoint]
    async def update_verification_point_state(...)
    
    # Evidence operations
    async def add_evidence(self, evidence: Evidence) -> None
    async def get_evidence_for_verification_point(self, vp_id: str) -> list[Evidence]
    async def get_evidence_for_answer(self, answer_id: str) -> list[Evidence]
    
    # Transition operations
    async def add_transition(self, transition: EvidenceTransition) -> None
    async def get_transitions_for_verification_point(self, vp_id: str) -> list[EvidenceTransition]
    
    # Contradiction operations
    async def add_contradiction(self, contradiction: Contradiction) -> None
    async def get_contradictions_for_verification_point(self, vp_id: str) -> list[Contradiction]
    async def get_contradictions_for_interview(self, interview_id: str) -> list[Contradiction]
    async def get_unresolved_contradictions_for_claim(self, claim_id: str) -> list[Contradiction]
```

**设计原则**:
- Repository不执行commit - 调用者负责事务管理
- 所有操作都是async
- 与InterviewRepository保持一致的模式

### Update Evidence Node Flow

```
Interview Answer
    ↓
Get/Create VerificationPoint from database
    ↓
Extract Evidence Spans (EvidenceSpanExtractor)
    ↓
Save Evidence records to database
    ↓
Detect Contradictions (ContradictionDetector)
    ↓
Save Contradiction records to database
    ↓
Determine Target State (based on evidence & contradictions)
    ↓
Check State Transition (EvidenceStateMachine.can_transition)
    ↓
Record EvidenceTransition to database
    ↓
Update VerificationPoint state in database
    ↓
Update Phase 1 claim_statuses (backward compatibility)
    ↓
Return updated state
```

**关键设计决策**:

1. **Database Session Management**
   ```python
   async with async_session_factory() as session:
       try:
           evidence_repo = EvidenceRepository(session)
           # ... operations ...
           await session.commit()
       except Exception as e:
           await session.rollback()
           # Fallback to Phase 1 behavior
   ```
   - 使用 `async_session_factory()` 而非依赖注入（LangGraph节点不支持FastAPI Depends）
   - 错误时回滚并fallback到Phase 1行为
   - 确保Phase 1测试不受影响

2. **State Transition Logic**
   ```python
   # Determine target state
   if has_contradictions:
       target_state = EvidenceState.CONTRADICTORY
   elif len(span_result.spans) > 0 and span_result.confidence >= 0.7 and not missing:
       target_state = EvidenceState.VERIFIED
   elif len(span_result.spans) > 0:
       target_state = EvidenceState.PARTIALLY_SUPPORTED
   elif addressed:
       target_state = EvidenceState.ADDRESSED
   else:
       target_state = current_state  # No transition
   
   # Check if transition allowed
   success, transition_reason, msg = state_machine.can_transition(
       current_state=current_state,
       target_state=target_state,
       context=context,
   )
   ```
   - 基于证据和矛盾确定目标状态
   - 使用state machine验证转换是否允许
   - 只有成功的转换才记录到数据库

3. **Phase 1 Compatibility**
   ```python
   # Phase 2: Evidence Engine processing
   # ... span extraction, contradiction detection, state transition ...
   
   # Phase 1: Maintain backward compatibility
   evidence_items.append(evidence.model_dump(mode="json"))
   
   if current_vp_id:
       if not missing and addressed:
           status["verified_points"].append(current_vp_id)
       elif addressed:
           status["partial_points"].append(current_vp_id)
       # ... more Phase 1 logic ...
   
   return {
       "claim_statuses": claim_statuses,  # Phase 1
       "coverage": coverage,               # Phase 1
       "evidence_items": evidence_items,   # Phase 1
       "contradictions": contradictions_list,  # Phase 2
   }
   ```
   - Phase 2处理在Phase 1逻辑之前执行
   - Phase 1输出字段完全保留
   - 错误时回退到纯Phase 1行为

4. **TransitionContext构建**
   ```python
   context = TransitionContext(
       verification_point_id=current_vp_id,
       interview_id=interview_id,
       answer_id=answer_id,
       has_evidence_spans=(len(span_result.spans) > 0),
       strength=span_result.confidence,
       confidence="HIGH" if span_result.confidence >= 0.8 else "MEDIUM" if span_result.confidence >= 0.5 else "LOW",
       has_contradiction=has_contradictions,
       contradiction_details={"description": ..., "severity": ...} if has_contradictions else None,
   )
   ```
   - 必需字段：verification_point_id, interview_id
   - 可选字段：answer_id, has_evidence_spans, strength, confidence, has_contradiction, contradiction_details
   - 为state machine guard conditions提供上下文

## 挑战与解决方案

### 挑战1: Database Session Management in LangGraph Nodes

**问题**: LangGraph节点不支持FastAPI的依赖注入，无法使用 `Depends(get_session)`

**解决方案**:
```python
from app.persistence.database import async_session_factory

async with async_session_factory() as session:
    try:
        evidence_repo = EvidenceRepository(session)
        # ... operations ...
        await session.commit()
    except Exception:
        await session.rollback()
        # Fallback
```

### 挑战2: TransitionContext字段不匹配

**问题**: 最初使用了错误的字段名（`has_contradictions` vs `has_contradiction`, `contradiction_severity` vs `contradiction_details`）

**解决方案**: 检查 `state_machine.py` 中的 `TransitionContext` dataclass定义，使用正确的字段名

### 挑战3: State Machine API理解

**问题**: 最初假设有 `transition()` 方法，实际上是 `can_transition()`

**解决方案**: 
- 使用 `can_transition()` 检查是否允许转换
- 手动更新VP状态（state machine不自动更新数据库）
- 基于evidence和contradictions确定target state

### 挑战4: Phase 1 Backward Compatibility

**问题**: 确保新的Evidence Engine 2.0不破坏Phase 1测试

**解决方案**:
- 保留所有Phase 1输出字段
- Phase 2处理在try-except中，错误时fallback到Phase 1
- Phase 1逻辑完全保留，仅添加Phase 2逻辑

## 设计决策记录

### 1. Repository Pattern for Evidence Operations

**决策**: 创建专门的 `EvidenceRepository` 而非在 `InterviewRepository` 中添加方法

**理由**:
- Evidence Engine 2.0是独立的领域模块
- 保持repository的单一职责
- 便于测试和维护
- 未来可能需要独立的evidence service

### 2. Database Session in LangGraph Nodes

**决策**: 使用 `async_session_factory()` 直接创建session

**理由**:
- LangGraph节点不支持FastAPI依赖注入
- `async_session_factory()` 是SQLAlchemy标准模式
- 保持与API层的一致性（同一个session factory）

### 3. Fallback to Phase 1 on Error

**决策**: Evidence Engine 2.0错误时回退到Phase 1行为

**理由**:
- 确保Phase 1功能不受影响
- 渐进式rollout，降低风险
- 便于调试和问题定位
- 保护现有用户体验

### 4. State Transition只在成功时记录

**决策**: 只有 `can_transition()` 返回success时才记录transition

**理由**:
- 避免记录无效的转换尝试
- EvidenceTransition表只记录实际发生的转换
- 保持audit trail的准确性
- Guard conditions确保业务规则
