#### 5. Claim Mapper 实现
**文件**: `app/planning/claim_mapper.py` (~350 LOC)

实现了 **Claim → Competency/Requirement 映射引擎**：

**核心功能**:
1. **Competency Mapping** - 将简历 Claim 映射到能力代码
   - 基于关键词匹配（23 个能力，每个 5-15 个关键词）
   - 支持中英文混合匹配（case-insensitive）
   - Mapping strength 评分规则：
     - 1 个关键词匹配: 0.6
     - 2 个关键词匹配: 0.75
     - 3+ 个关键词匹配: 0.9
   - 可配置最小强度阈值（默认 0.5）

2. **Requirement Mapping** - 将 Claim 映射到岗位需求
   - 基于已有的 Competency Mapping
   - Title boost: 如果 requirement title 出现在 claim 中，relevance +0.15
   - Coverage level 估算（1-5 级，保守估计 1-2 级）
   - 可配置最小相关性阈值（默认 0.4）

3. **Integrated Mapping** - `map_claim()` 统一接口
   - 同时返回 competency 和 requirement mappings
   - 结果按相关性/强度降序排列

**数据模型**:
```python
class CompetencyMapping(BaseModel):
    claim_id: str
    competency_code: str
    mapping_strength: float  # 0.0-1.0
    mapping_reason: str

class RequirementMapping(BaseModel):
    claim_id: str
    requirement_id: str
    competency_code: str
    relevance: float         # 0.0-1.0
    coverage_level: int      # 0-5
    mapping_reason: str

class ClaimMappingResult(BaseModel):
    claim_id: str
    claim_text: str
    competency_mappings: list[CompetencyMapping]
    requirement_mappings: list[RequirementMapping]
```

**关键词示例**（部分）:
- `backend.cache`: redis, cache, 缓存, memcached, 缓存穿透, 缓存击穿, 缓存雪崩
- `backend.message_queue`: kafka, rabbitmq, mq, 消息队列, pulsar, pub/sub
- `agent.prompt_design`: prompt, few-shot, chain-of-thought, cot, 提示词
- `agent.rag_fundamentals`: rag, retrieval, embedding, 向量, vector, 检索增强

## 架构决策记录

### Claim Mapper 设计原则

1. **Rule-based vs LLM-assisted**
   - ✅ 当前实现：Pure rule-based（关键词匹配）
   - 理由：快速、可预测、可测试、无 API 成本
   - 未来扩展：保留 `LLMGateway` 接口，可用于歧义消解
   - `use_llm_fallback` flag 预留（当前未使用）

2. **Keyword Coverage Strategy**
   - ✅ 每个 competency 5-15 个关键词
   - 包含技术名称（Redis, Kafka, LangGraph）
   - 包含通用术语（cache, message queue, prompt）
   - 包含中文术语（缓存, 消息队列, 提示词）
   - 包含领域特有术语（缓存穿透, few-shot, goroutine）

3. **Mapping Strength Formula**
   - 1 keyword: 0.6 (低置信度，但可能相关)
   - 2 keywords: 0.75 (中等置信度)
   - 3+ keywords: 0.9 (高置信度)
   - 不使用 1.0，保留人工确认空间

4. **Requirement Relevance Calculation**
   - Base relevance = competency mapping strength
   - Title boost = +0.15 (如果 requirement title 出现在 claim)
   - Coverage level = 保守估计（1-2 级，需面试验证）

5. **Filtering Thresholds**
   - Competency: 默认 min_strength = 0.5（过滤 1 keyword 的弱匹配）
   - Requirement: 默认 min_relevance = 0.4（更宽松，避免漏过相关需求）

### 立即实现

#### 1. Claim Gap Analyzer
**文件**: `app/planning/claim_gap_analyzer.py`

**功能**:
- Gap 分类（5 类）：
  1. `SUPPORTED_CLAIM` - Claim 有证据支持
  2. `WEAK_EVIDENCE_CLAIM` - Claim 存在但证据不足
  3. `HIGH_PRIORITY_WEAK_EVIDENCE` - 高优先级需求但证据弱
  4. `UNCOVERED_REQUIREMENT` - 岗位需求但简历未提及
  5. `IRRELEVANT_CLAIM` - Claim 与岗位无关

- Priority 评分公式:
  ```python
  priority = (
      job_importance * 0.4 +
      evidence_gap * 0.3 +
      claim_risk * 0.2 +
      verification_value * 0.1
  )
  ```

- Reason codes 生成:
  - `REQUIREMENT_UNCOVERED` - 岗位要求但未覆盖
  - `CLAIM_WEAK_EVIDENCE` - Claim 存在但需深度验证
  - `HIGH_IMPORTANCE_GAP` - 高重要性需求缺失
  - `CONTRADICTORY_CLAIMS` - Claim 之间有矛�盾

**输入**:
```python
ClaimMappingResult[]  # 来自 ClaimMapper
JobRequirement[]      # 来自 JobTarget
```

**输出**:
```python
ClaimGapResult(
    gaps=[
        Gap(
            gap_type="HIGH_PRIORITY_WEAK_EVIDENCE",
            claim_id="claim_1",
            requirement_id="req_1",
            competency_code="backend.cache",
            priority=0.85,
            reason_codes=["HIGH_IMPORTANCE_GAP", "CLAIM_WEAK_EVIDENCE"],
            explanation="Redis 缓存是核心需求(0.9)，但 claim 仅提及基础使用"
        ),
        ...
    ],
    coverage_stats={
        "total_requirements": 8,
        "covered_requirements": 5,
        "uncovered_requirements": 3,
        "weak_evidence_count": 2,
    }
)
```

## 关键洞察

### Claim Mapper 优势
1. ✅ **快速**：纯规则，无 API 调用，毫秒级响应
2. ✅ **可预测**：相同输入总是相同输出
3. ✅ **可测试**：规则明确，易于编写测试
4. ✅ **可扩展**：保留 LLM 接口，可逐步增强
5. ✅ **成本低**：无 LLM API 成本

### Claim Mapper 局限
1. ⚠️ **关键词维护**：需要持续补充和调整
2. ⚠️ **语义理解有限**：无法处理复杂的语义变体
3. ⚠️ **歧义消解能力弱**：相似关键词可能误匹配

### 未来增强方向
1. 🔮 LLM-assisted ambiguity resolution（当规则匹配不确定时调用 LLM）
2. 🔮 向量相似度匹配（embedding-based matching）
3. 🔮 用户反馈学习（记录人工修正，调整权重）
