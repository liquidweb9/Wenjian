## 架构决策记录

### Template 设计原则

1. **预定义 vs 动态生成**
   - ✅ 选择：预定义模板 + 用户可编辑
   - 理由：预定义保证质量，可编辑提供灵活性
   - JD Parser 将用于动态生成，但用户必须确认/编辑

2. **Importance 权重范围**
   - ✅ 使用 0.6-1.0 范围（避免 0.0-0.5 的低重要性需求）
   - 理由：如果某个能力不重要，就不应该出现在 template 中
   - 0.6-0.7: 基础要求
   - 0.7-0.85: 常规要求
   - 0.85-1.0: 核心要求

3. **Expected Level 设定**
   - Intern: L1-L2
   - Junior: L2
   - Mid: L2-L3（核心能力 L3）
   - Senior: L3-L4
   - Staff: L4-L5

4. **Evidence Expectation 数量**
   - 每个 requirement 2-3 个 evidence points
   - 描述具体可验证行为（非泛泛而谈）
   - 中文描述可以简洁（7+ 字符）

## 下一步（M2.1 Part 3）

### 立即实现

#### 1. JD Parser
**文件**: `app/job_target/jd_parser.py`
- LLM 从 JD 文本提取结构化 requirements
- Schema validation（确保输出符合 `RequirementTemplate` 格式）
- Source span 追踪（链接回 JD 原文位置）
- Competency code 推断（基于 requirement 描述）

**输入**:
```python
raw_jd = """
后端工程师 - 中级

职责：
- 设计和开发微服务架构
- 优化数据库查询性能
- 实现 Redis 缓存方案
...
"""
```

**输出**:
```python
[
    RequirementTemplate(
        competency_code="backend.system_design",
        title="微服务架构设计",
        description="设计和开发微服务架构",
        importance=0.85,
        expected_level=3,
        evidence_expectation=[...],
        source_span={"start": 20, "end": 35, "text": "设计和开发微服务架构"}
    ),
    ...
]
```

#### 2. Claim Mapper
**文件**: `app/planning/claim_mapper.py`
- Claim → Competency 映射（使用规则 + LLM 辅助）
- Claim → Requirement 映射（计算 relevance）
- Mapping strength 计算（0.0-1.0）

**示例**:
```python
claim = "我使用 Redis 实现了订单缓存"
→ competency_code = "backend.cache"
→ mapping_strength = 0.9
→ mapping_reason = "Claim 明确提到 Redis 缓存实现"
```
