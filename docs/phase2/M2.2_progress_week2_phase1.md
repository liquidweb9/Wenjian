## 本次完成工作

### Evidence Span Extractor ✅

**文件**: `app/evidence/span_extractor.py` (~220 LOC)

**核心功能**:
- LLM驱动的evidence span提取
- 支持3种证据类型（DIRECT/INDIRECT/CONTEXTUAL）
- Quote hash计算（SHA256前16位，防篡改）
- Span验证逻辑（位置、长度、文本匹配）
- 结构化输出（Pydantic schema）

**数据结构**:
```python
@dataclass
class EvidenceSpan:
    answer_id: str
    start: int
    end: int
    text: str
    quote_hash: str  # sha256:abc123...
    evidence_type: str  # DIRECT/INDIRECT/CONTEXTUAL

@dataclass
class ExtractionResult:
    spans: list[EvidenceSpan]
    summary: str
    confidence: float
    extracted_by: str = "MODEL"
```

**提取流程**:
```
Interview Answer
    ↓
LLM Extraction (structured output)
    ↓
Span Validation (position, length, text match)
    ↓
Hash Calculation (SHA256)
    ↓
ExtractionResult (spans + summary + confidence)
```

**关键特性**:

1. **Structured Output with Pydantic**
   - `EvidenceSpanOutput` schema确保LLM输出格式正确
   - 字段验证（confidence 0.0-1.0, summary最小10字符）
   - 类型安全

2. **Span Validation**
   - 位置有效性：`0 <= start < end <= len(answer_text)`
   - 文本匹配：提取的文本必须与answer中实际文本匹配
   - 归一化匹配：允许空格差异（`" ".join(text.split())`）
   - 最小长度：至少5个字符

3. **Quote Hash**
   - SHA256哈希的前16位
   - 格式：`sha256:abc123def456...`
   - 用途：验证span未被篡改

4. **Evidence Types**
   - **DIRECT**: 明确陈述（"I implemented Redis caching"）
   - **INDIRECT**: 暗示性证据（"team relied on my expertise"）
   - **CONTEXTUAL**: 背景信息

## 架构亮点

### 1. Protocol-Based LLM Interface

```python
class LLMGateway(Protocol):
    async def generate_structured(
        self,
        task_name: str,
        messages: list[dict],
        output_model: type[BaseModel],
        temperature: float = 0.0,
    ) -> BaseModel:
        ...
```

- 依赖Protocol而非具体实现
- 易于测试（MockLLMGateway）
- 解耦LLM provider

### 2. Flexible Validation

```python
def _validate_span(self, span_data: dict, answer_text: str) -> bool:
    # 1. 检查必需字段
    # 2. 检查位置有效性
    # 3. 检查最小长度
    # 4. 归一化文本匹配
    # 5. 允许substring匹配（LLM可能提取清洁版本）
```

- 容错性：允许空格差异
- 严格性：位置和长度必须正确
- 实用性：LLM提取的文本可能略有不同

### 3. Prompt Engineering

Prompt结构：
- 明确任务：提取支持/反驳verification aspect的证据
- 输入上下文：verification aspect + expected evidence + answer text
- 输出格式：JSON schema with spans/summary/confidence
- 约束规则：exact quotes, position validation, relevance filtering

## 设计决策记录

### 1. Protocol vs Concrete LLM Gateway

**决策**: 使用Protocol定义LLMGateway接口

**理由**:
- 测试时可用MockLLMGateway
- 不依赖具体的AgnesGateway实现
- 未来可切换LLM provider

### 2. Span Validation Strictness

**决策**: 严格验证位置，宽松验证文本

**理由**:
- 位置必须准确（用于前端高亮）
- 文本可以有空格差异（LLM可能格式化）
- Substring匹配允许LLM提取清洁版本

### 3. Hash Length (16 chars)

**决策**: 使用SHA256的前16位而非完整64位

**理由**:
- 16位足够唯一（碰撞概率极低）
- 更短的数据库存储
- 更易读的日志

### 4. Three Evidence Types

**决策**: DIRECT/INDIRECT/CONTEXTUAL三种类型

**理由**:
- **DIRECT**: 可直接用于VERIFIED状态
- **INDIRECT**: 需要更多证据支持
- **CONTEXTUAL**: 提供背景，不直接验证
- 未来可用于加权计算strength
