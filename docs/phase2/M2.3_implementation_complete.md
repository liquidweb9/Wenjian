## Implementation Summary

### 1. PromptRegistry (`app/evals/prompt_registry.py`)

**Purpose**: Version-controlled prompt management for reproducible LLM behavior.

**Key Features**:
- Register prompts with semantic versioning
- Load prompts by task_name + version (or latest active)
- Cache prompts in memory for performance
- Deactivate old versions without deletion
- Load bulk prompts from JSON files

**API**:
```python
registry = get_prompt_registry()

# Register a prompt
await registry.register_prompt(
    task_name="score_answer",
    version=1,
    system_prompt="...",
    rules="...",
    examples=[...]
)

# Get specific version
spec = await registry.get_prompt("score_answer", version=1)

# Get latest active version
spec = await registry.get_prompt("score_answer")

# List all versions
versions = await registry.list_versions("score_answer")
```

**Database**: Uses existing `prompt_versions` table (already in models.py from Phase 1).

---

### 2. RubricVersioning (`app/evals/rubric_versioning.py`)

**Purpose**: Track rubric changes to ensure fair score comparisons across time.

**Key Features**:
- Register rubrics with dimension weights and descriptors
- Load rubrics by name + version
- Validate evaluations against rubric schema
- Calculate weighted scores using rubric weights
- Compare rubric versions (detect compatibility)

**API**:
```python
registry = get_rubric_registry()

# Register a rubric
await registry.register_rubric(
    rubric_name="answer_scoring",
    version=1,
    dimension_weights={"technical_correctness": 25, ...},
    dimension_descriptors={"technical_correctness": "...", ...}
)

# Get rubric
spec = await registry.get_rubric("answer_scoring", version=1)

# Validate evaluation
spec.validate_evaluation(evaluation_dict)

# Calculate weighted score
score = spec.calculate_weighted_score(evaluation_dict)

# Compare versions
comparison = await registry.compare_versions("answer_scoring", 1, 2)
# Returns: {compatible: bool, dimensions_added: [...], weight_diff: {...}}
```

**Database**: New `rubric_versions` table added to `models.py`.

### 4. Updated Eval Runner (`app/evals/runner.py`)

**Purpose**: Support both mock (Phase 1) and LLM-based (Phase 2) evaluation modes.

**Changes**:
- Added `use_llm` parameter to `run_baseline_evaluation()`
- Added `prompt_version` and `rubric_version` parameters
- Supports CLI flag: `python -m app.evals.runner --llm`

**Usage**:
```bash
# Mock-based (fast, for development)
python -m app.evals.runner

# LLM-based (real evaluation)
python -m app.evals.runner --llm
```

**Metrics Calculated**:
- **Scoring**: MAE per dimension, overall MAE, level agreement rate, dimension miss rate
- **Routing**: Accuracy, invalid route rate, premature switch rate, confusion matrix
- **Evidence**: Status accuracy, VERIFIED false positive rate, contradiction precision/recall, strength MAE

### 5. Eval Gate (`app/evals/eval_gate.py`)

**Purpose**: CI gate that blocks merges if LLM prompt/rubric changes cause regressions.

**Regression Thresholds**:
```python
REGRESSION_THRESHOLDS = {
    "scoring": {
        "overall_mae": 2.0,           # MAE increase > 2.0 blocks merge
        "level_agreement_rate": -0.10, # 10% drop blocks merge
    },
    "routing": {
        "accuracy": -0.15,             # 15% drop blocks merge
        "invalid_route_rate": 0.05,    # 5% increase blocks merge
    },
    "evidence": {
        "status_accuracy": -0.15,
        "verified_false_positive_rate": 0.10,
    },
}
```

**Usage in CI**:
```bash
# Run eval gate against baseline
python -m app.evals.eval_gate \
    --baseline baseline_results.json \
    --output current_results.json \
    --use-llm

# Exit codes:
# 0 = No regression (allow merge)
# 1 = Regression detected (block merge)
# 2 = Error
```

**Report Format**:
```
======================================================================
EVAL GATE REPORT
======================================================================

❌ REGRESSION DETECTED - Merge blocked

Regressions:
  • scoring.overall_mae
    Baseline: 2.500
    Current:  4.500
    Delta:    +2.000 (threshold: +2.000)

Improvements:
  • routing.accuracy
    Baseline: 0.800
    Current:  0.850
    Delta:    +0.050
```

## Architecture Patterns

### 1. Version-Controlled Prompts
Every LLM call can specify prompt version:
```python
# Development: use latest
spec = await registry.get_prompt("score_answer")

# Production: pin to specific version
spec = await registry.get_prompt("score_answer", version=1)
```

### 2. Rubric Compatibility
Rubrics can be compared to determine if scores are comparable:
```python
comparison = await registry.compare_versions("answer_scoring", 1, 2)

if not comparison["compatible"]:
    # Dimensions changed - can't compare scores
    raise ValueError("Cannot compare scores across rubric versions")
```

### 3. Regression Detection
Eval gate compares current performance against baseline:
```python
baseline = load_baseline("phase1_baseline.json")
current = run_baseline_evaluation(use_llm=True)
comparison = compare_results(baseline, current)

if comparison["has_regression"]:
    sys.exit(1)  # Block merge
```

## CI/CD Integration

### Recommended GitHub Actions Workflow
```yaml
name: Eval Gate

on:
  pull_request:
    paths:
      - 'app/interview/**'
      - 'app/evals/prompts/**'

jobs:
  eval-gate:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3
      - name: Setup Python
        uses: actions/setup-python@v4
        with:
          python-version: '3.12'
      
      - name: Install dependencies
        run: pip install -e ".[dev]"
      
      - name: Run eval gate
        run: |
          python -m app.evals.eval_gate \
            --baseline evals/baseline_v1.json \
            --output current_eval.json \
            --use-llm
        env:
          LLM_API_KEY: ${{ secrets.LLM_API_KEY }}
      
      - name: Upload results
        if: failure()
        uses: actions/upload-artifact@v3
        with:
          name: eval-results
          path: current_eval.json
```
