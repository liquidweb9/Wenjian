#### 6. Claim Gap Analyzer 实现
**文件**: `app/planning/claim_gap_analyzer.py` (~430 LOC)

实现了 **Claim Gap 分析和优先级排序引擎**：

**核心功能**:
1. **Gap 分类（5 种类型）**:
   - `UNCOVERED_REQUIREMENT`: 岗位需求但简历未提及
   - `HIGH_PRIORITY_WEAK_EVIDENCE`: 高优先级需求但证据薄弱
   - `WEAK_EVIDENCE_CLAIM`: Claim 存在但覆盖度不足
   - `SUPPORTED_CLAIM`: Claim 有良好证据支持
   - `IRRELEVANT_CLAIM`: Claim 与岗位无关

2. **Reason Codes（6 种原因）**:
   - `REQUIREMENT_UNCOVERED`: 需求未覆盖
   - `CLAIM_WEAK_EVIDENCE`: 证据不足
   - `HIGH_IMPORTANCE_GAP`: 高重要性缺口
   - `LOW_COVERAGE_LEVEL`: 覆盖级别低于期望
   - `CONTRADICTORY_CLAIMS`: Claim 之间矛盾
   - `IRRELEVANT_TO_JOB`: 与岗位无关

3. **优先级评分公式**:
   ```python
   # Uncovered requirement
   priority = importance * 0.9

   # Weak evidence
   priority = (
       importance * 0.4 +
       evidence_gap * 0.3 +
       (1.0 - relevance) * 0.2 +
       verification_value * 0.1
   )

   # Supported claim
   priority = importance * 0.3 + relevance * 0.1
   ```

4. **Coverage Statistics**:
   - Total requirements / Covered / Uncovered
   - Weak evidence count
   - High-priority gaps count (priority >= 0.7)
   - Coverage percentage

5. **High-Priority Targets**:
   - 自动识别 priority >= 0.7 的 gaps
   - 返回 claim_id 或 requirement_id 列表
   - 用于 Interview Plan 生成

**数据模型**:
```python
class Gap(BaseModel):
    gap_type: GapType
    claim_id: str | None
    requirement_id: str | None
    competency_code: str
    priority: float  # 0.0-1.0
    reason_codes: list[ReasonCode]
    explanation: str
    # Context fields
    claim_text: str | None
    requirement_title: str | None
    requirement_importance: float | None
    requirement_expected_level: int | None
    claim_coverage_level: int | None

class ClaimGapResult(BaseModel):
    gaps: list[Gap]  # Sorted by priority descending
    coverage_stats: CoverageStats
    high_priority_targets: list[str]
```

## 架构决策记录

### Gap Analysis 设计原则

1. **Gap 类型层次**
   - ✅ UNCOVERED > HIGH_PRIORITY_WEAK > WEAK_EVIDENCE > SUPPORTED > IRRELEVANT
   - 优先级反映面试验证的紧迫性
   - SUPPORTED claim 也需验证，但优先级低

2. **Priority 评分策略**
   - Uncovered: importance * 0.9 (最高优先级)
   - Weak evidence: 综合考虑 importance, evidence_gap, relevance, verification_value
   - Supported: importance * 0.3 + relevance * 0.1 (最低优先级)
   - 所有评分在 0.0-1.0 范围内

3. **Coverage Level vs Expected Level**
   - Coverage level: Claim Mapper 保守估计（通常 1-2 级）
   - Expected level: Job requirement 期望（1-5 级）
   - Gap = expected - coverage
   - Coverage >= expected → SUPPORTED
   - Coverage < expected → WEAK_EVIDENCE
   - Coverage < expected && importance >= 0.8 → HIGH_PRIORITY_WEAK

4. **High-Priority Threshold**
   - Priority >= 0.7 → 列入 high_priority_targets
   - 用于 Interview Plan 优先选择
   - 通常包括：uncovered high-importance, high-priority weak evidence

5. **Coverage Statistics**
   - Covered = has at least one claim mapping (regardless of quality)
   - Uncovered = no claim mapping at all
   - Weak evidence = covered but coverage < expected
   - Coverage % = covered / total (粗略指标)

## 示例：完整 Claim Gap 分析流程

```python
# 1. 解析 JD
jd_parser = JDParser(llm=gateway)
jd_result = await jd_parser.parse_jd(jd_text)

# 2. 创建 Job Target
requirements = [
    {
        "requirement_id": "req_1",
        "competency_code": "backend.cache",
        "title": "Redis 缓存",
        "importance": 0.9,
        "expected_level": 3,
    },
    {
        "requirement_id": "req_2",
        "competency_code": "backend.message_queue",
        "title": "Kafka 消息队列",
        "importance": 0.85,
        "expected_level": 3,
    },
]

# 3. Map Claims
mapper = ClaimMapper()
claim_mappings = [
    mapper.map_claim(
        claim_id=claim.claim_id,
        claim_text=claim.text,
        requirements=requirements,
    )
    for claim in resume_claims
]

# 4. Analyze Gaps
analyzer = ClaimGapAnalyzer()
gap_result = analyzer.analyze_gaps(claim_mappings, requirements)

# 5. Results
print(f"Coverage: {gap_result.coverage_stats.coverage_percentage:.0%}")
print(f"High-priority gaps: {gap_result.coverage_stats.high_priority_gaps}")
for gap in gap_result.gaps[:5]:  # Top 5
    print(f"  [{gap.gap_type}] {gap.explanation} (priority={gap.priority:.2f})")
```

**示例输出**:
```
Coverage: 67%
High-priority gaps: 2

[UNCOVERED_REQUIREMENT] Job requires Kafka (importance 0.85), but no matching claim found (priority=0.77)
[HIGH_PRIORITY_WEAK_EVIDENCE] Redis is high priority (importance 0.90), but evidence is weak (coverage L2, expected L3) (priority=0.62)
[WEAK_EVIDENCE_CLAIM] Claim mentions MySQL, but coverage (L1) is below expected (L3) (priority=0.48)
[SUPPORTED_CLAIM] API 设计 appears well-supported by claim (coverage L2, expected L2) (priority=0.32)
[IRRELEVANT_CLAIM] Claim doesn't relate to any job requirement (priority=0.10)
```
