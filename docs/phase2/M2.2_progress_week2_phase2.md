## 本次完成工作

### Contradiction Detector ✅

**文件**: `app/evidence/contradiction_detector.py` (~250 LOC)

**核心功能**:
- LLM驱动的矛盾检测
- 支持4种矛盾类型（FACTUAL/TIMELINE/ROLE/SCOPE）
- 3级严重性评估（LOW/MEDIUM/HIGH）
- 自动生成澄清问题
- 结构化输出（Pydantic schema）

**数据结构**:
```python
@dataclass
class Contradiction:
    contradiction_id: str
    verification_point_id: str
    conflicting_answers: list[dict]  # [{"answer_id": "...", "text": "...", "question": "..."}]
    contradiction_type: str  # FACTUAL/TIMELINE/ROLE/SCOPE
    severity: str  # LOW/MEDIUM/HIGH
    description: str
    clarification_question: str

@dataclass
class DetectionResult:
    contradictions: list[Contradiction]
    overall_consistency: str
    confidence: float
```

**矛盾类型**:

1. **FACTUAL** (事实矛盾)
   - 例子：「我使用了Redis」vs「我们使用了Memcached」
   - 严重性：通常为MEDIUM/HIGH
   - 最严重的矛盾类型

2. **TIMELINE** (时间线矛盾)
   - 例子：「6个月项目」vs「3个月冲刺」
   - 严重性：通常为MEDIUM
   - 可能由上下文解释

3. **ROLE** (角色矛盾)
   - 例子：「我设计了系统」vs「团队设计，我实现」
   - 严重性：通常为MEDIUM
   - 需要澄清具体贡献

4. **SCOPE** (范围矛盾)
   - 例子：「完整重写」vs「渐进式重构」
   - 严重性：通常为LOW/MEDIUM
   - 上下文可能解释差异

**检测流程**:
```
Multiple Answers (≥2)
    ↓
LLM Detection (structured output)
    ↓
Contradiction Validation (type, severity, answer_ids)
    ↓
Clarification Question Generation
    ↓
DetectionResult (contradictions + consistency + confidence)
```

**关键特性**:

1. **Structured Output with Pydantic**
   - `ContradictionOutput` schema确保LLM输出格式正确
   - 字段验证（confidence 0.0-1.0, overall_consistency最小10字符）
   - 类型安全

2. **Contradiction Validation**
   - 类型有效性：只接受FACTUAL/TIMELINE/ROLE/SCOPE
   - 严重性有效性：只接受LOW/MEDIUM/HIGH
   - 冲突答案数量：至少2个conflicting_answers
   - Answer ID验证：确保引用的answer存在
   - 描述长度：至少10个字符

3. **Clarification Question Templates**
   - 每种矛盾类型有专门的澄清问题模板
   - 包含verification aspect上下文
   - 包含矛盾描述
   - 示例：
     ```
     FACTUAL: "I noticed some inconsistency regarding {aspect}. 
              {description} Could you clarify which information is accurate?"
     
     TIMELINE: "There seems to be some timeline inconsistency about {aspect}. 
               {description} Could you clarify the exact timeline?"
     
     ROLE: "I'd like to understand your role better in {aspect}. 
           {description} Could you clarify your specific contributions?"
     
     SCOPE: "I want to make sure I understand the scope of {aspect}. 
            {description} Could you clarify the actual scope?"
     ```

4. **Early Return for Insufficient Data**
   - 少于2个答案时直接返回空结果
   - 避免无意义的LLM调用
   - confidence设为0.0

### 3. Prompt Engineering

Prompt结构：
- 明确任务：分析多个答案之间的矛盾
- 矛盾类型定义：4种类型的明确描述和示例
- 输入上下文：verification aspect + expected evidence + answers
- 输出格式：JSON schema with contradictions/overall_consistency/confidence
- 约束规则：只标记明确矛盾，考虑上下文，评估严重性

**Prompt关键原则**:
- "Only flag clear contradictions, not minor wording differences"
- "Consider context - answers may complement rather than contradict"
- "FACTUAL contradictions are most serious (typically MEDIUM/HIGH severity)"
- "TIMELINE/ROLE/SCOPE may be LOW severity if context explains the difference"

## 设计决策记录

### 1. 4种矛盾类型

**决策**: FACTUAL/TIMELINE/ROLE/SCOPE四种类型

**理由**:
- **FACTUAL**: 技术选型、数据量等客观事实矛盾
- **TIMELINE**: 项目周期、里程碑等时间矛盾
- **ROLE**: 个人贡献vs团队协作的角色矛盾
- **SCOPE**: 项目范围、复杂度等规模矛盾
- 覆盖了面试中最常见的矛盾场景
- 每种类型有不同的澄清策略

### 2. 3级严重性

**决策**: LOW/MEDIUM/HIGH三级严重性

**理由**:
- **LOW**: 可能由上下文解释，不影响整体可信度
- **MEDIUM**: 需要澄清但不一定是撒谎
- **HIGH**: 严重矛盾，可能影响候选人评估
- FACTUAL矛盾通常是HIGH，其他类型可能是LOW/MEDIUM
- 严重性影响是否触发CONTRADICTORY状态

### 3. Answer数量要求

**决策**: 至少2个答案才检测矛盾

**理由**:
- 1个答案无法构成矛盾
- 早期返回避免无意义的LLM调用
- confidence=0.0标识数据不足

### 4. 自动生成澄清问题

**决策**: 基于矛盾类型自动生成澄清问题

**理由**:
- 每种类型有专门的模板
- 包含具体的verification aspect和矛盾描述
- 面试官可直接使用或调整
- 支持NEEDS_CLARIFICATION状态
