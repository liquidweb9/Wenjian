## 已完成工作

### 1. ✅ 数据库 Schema 扩展

在 `app/persistence/models.py` 添加了 5 个新表（80+ LOC）:

#### Phase 2 核心表
- **`Competency`**: 能力目录定义
  - 字段：code（唯一索引）, domain, title, description, level_descriptors, is_active
  - 用途：定义可评估的技能和能力（backend/agent）

- **`JobTarget`**: 岗位目标定义
  - 字段：title, company_name, level, interview_round, source, raw_jd, parser_prompt_version, is_template
  - 用途：可以是模板或用户创建的岗位

- **`JobRequirement`**: 从 JD 提取的结构化要求
  - 字段：job_target_id (FK), competency_code, title, description, importance, expected_level, evidence_expectation, source_span
  - 用途：链接岗位到具体能力要求

- **`ClaimCompetencyMapping`**: 简历 Claim → Competency 映射
  - 字段：claim_id (FK), competency_code, mapping_strength, mapping_reason, mapping_source, prompt_version
  - 用途：建立简历声明与能力的关联

- **`ClaimRequirementMapping`**: Claim → JobRequirement 映射（Gap 分析）
  - 字段：claim_id (FK), requirement_id (FK), relevance, evidence_strength, verification_priority, reason_codes
  - 用途：计算 Claim Gap，生成优先级

## 架构决策

### 1. 能力级别定义方式
- ✅ 使用行为描述而非模糊标签（"高级"→"能设计 Redis 集群，处理缓存预热"）
- ✅ 级别递进清晰（L1 基础语法 → L5 运行时内核贡献）
- ✅ 可观察性强，便于面试验证

### 2. Competency vs Dimension
- 保留现有 6 维度评分（technical_correctness, implementation_depth, etc.）
- Competency 是能力目录（用于岗位要求、Claim 映射）
- Dimension 是单次回答评分（用于分析回答质量）
- 两者分离：Dimension → Competency proficiency 需要聚合逻辑（M2.5）

### 3. Phase 2 范围控制
- ✅ 仅覆盖 backend + agent（23 个能力）
- ❌ 不包含 frontend, mobile, data science, PM（控制范围）
- ✅ M2.1 后冻结 catalog（防止无限扩张）

## 下一步（M2.1 Part 2）

### 待实现模块

#### 1. Job Target Templates（岗位模板）
**文件**: `app/job_target/templates.py`
- 6 个内置模板（Java 后端、Go 后端、Python 后端、AI Agent、RAG、实习生）
- 每个模板预定义 competency requirements + importance + expected_level

#### 2. JD Parser（JD 解析器）
**文件**: `app/job_target/jd_parser.py`
- LLM 提取 JD 中的结构化要求
- Schema validation（确保输出符合 JobRequirement 格式）
- Source span 追踪（链接回 JD 原文）

#### 3. Claim Mapper（Claim 映射器）
**文件**: `app/planning/claim_mapper.py`
- Claim → Competency 映射（计算 mapping_strength）
- Claim → Requirement 映射（计算 relevance）
- 使用规则 + LLM 辅助

#### 4. Claim Gap Analyzer（Gap 分析器）
**文件**: `app/planning/claim_gap.py`
- Gap 分类逻辑：
  - `SUPPORTED_CLAIM`: 有强证据
  - `HIGH_PRIORITY_WEAK_EVIDENCE`: 岗位重要但证据不足
  - `UNCOVERED_REQUIREMENT`: 岗位需要但简历无
  - `LOW_RELEVANCE_CLAIM`: 简历有但与岗位关系弱
  - `CONTRADICTORY_CLAIM`: 存在未解决矛盾
- Priority 评分公式：`job_importance × evidence_gap × claim_risk × ...`

#### 5. Interview Plan 更新
**文件**: `app/interview/nodes/build_plan.py`（修改）
- 从 Claim Gap 生成面试计划
- 每个 target 附带 reason_codes（解释为什么选择）
- 优先级排序（最重要的问题先问）

#### 6. API Endpoints
**文件**: `app/api/v1/job_targets.py`（新建）
- POST `/api/v1/job-targets` - 创建岗位
- GET `/api/v1/job-targets/{id}` - 获取岗位
- POST `/api/v1/job-targets/{id}/parse-jd` - 解析 JD
- PATCH `/api/v1/job-targets/{id}/requirements/{req_id}` - 编辑要求
- POST `/api/v1/resumes/{resume_id}/claim-gap` - 生成 Claim Gap

#### 7. 前端（Phase 2）
**目录**: `frontend-react/src/features/job-target/`
- Job target 选择页面（模板 + JD 粘贴）
- JD requirement 编辑器（CRUD）
