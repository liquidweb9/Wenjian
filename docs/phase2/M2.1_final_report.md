### 2. 核心算法

**Claim Mapper** - 关键词匹配：
- 1 keyword匹配 → strength 0.6
- 2 keywords匹配 → strength 0.75
- 3+ keywords匹配 → strength 0.9
- 支持中英文混合（case-insensitive）

**Gap Analyzer** - 优先级评分：
```python
# Uncovered requirement
priority = importance * 0.9

# Weak evidence
priority = (
    importance * 0.4 +
    evidence_gap * 0.3 +
    (1.0 - relevance) * 0.2 +
    verification_value * 0.1
)

# Supported claim  
priority = importance * 0.3 + relevance * 0.1
```

**Plan Builder** - 面试目标选择：
- 所有高优先级gaps（priority >= 0.7）
- 所有弱证据claims（需验证）
- 采样2个支持良好的claims（验证准确性）
- 排除无关claims

### 3. 数据完整性

- **Pydantic Models** - 所有API请求/响应类型安全
- **Schema Validation** - JD Parser输出验证
- **Competency Code验证** - 必须匹配catalog
- **Foreign Key约束** - 数据库关系完整性

### 4. 测试策略

## 使用场景示例

### 场景1：从JD创建Job Target

```
1. 用户导航到 /job-targets/new
2. 选择"粘贴JD文本"
3. 粘贴JD，点击"解析"
4. 系统调用JDParser，返回结构化requirements
5. 用户编辑/调整requirements
6. 保存job target
```

### 场景2：分析Resume与Job Target的Gap

```
1. 用户在Resume详情页选择Job Target
2. 点击"分析Gap"
3. 系统分析：
   - ClaimMapper: Resume Claims → Competency/Requirement Mappings
   - GapAnalyzer: Mappings → Gaps (5类型) + Priority
   - PlanBuilder: Gaps → Interview Targets
4. 显示Gap可视化页面：
   - Coverage: 67%
   - Gaps: 3个uncovered, 2个weak evidence
   - High-priority targets: 5个
5. 用户点击"启动面试"，传递interview targets
```

### 场景3：基于Gap启动面试

```
1. 从Claim Gap页面点击"启动面试"
2. Interview创建API接收interview targets
3. InterviewGraph使用targets生成问题
4. 每个问题关联到specific gap/claim/requirement
5. 面试报告显示gap验证结果
```
